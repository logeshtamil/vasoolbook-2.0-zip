# VasoolBook Workflow Audit & Test Checklist

**Audit date:** 2026-08-09  
**Audited application:** legacy Capacitor/WebView VasoolBook, package `in.vasoolbook.app`  
**Application package version:** `2.4.43`  
**Audit mode:** read-only. No production data, source logic, schema, settings, or APK was changed.

## Status key

- **PASS-A:** covered by a passing automated source/runtime test.
- **MANUAL:** must be verified in a browser or Android device; not claimed as passed by this audit.
- **FAIL:** an observed automated test failure.
- **RISK:** source-level risk found; no data was altered to prove or repair it.

## Evidence summary

- Test inventory: **45 passing / 1 failing** Node test files.
- The aggregate `npm.cmd run test:data-integrity` reaches `tests/interest-rounding.test.js` and stops there.
- The failure is a stale integration assertion, not proof that the current rounding implementation is wrong: `_roundInterestDown10()` now rounds **up to the nearest Rs.5**, while the test still checks a removed older source expression.
- SQLite activation, migration staging, recovery isolation, loan/payment ledger, Next Week, borrower area mapping, cloud adapters, gateway client, interest allocation, reports, messages, and UI performance have automated coverage. Native device/provider behavior remains manual.

## Findings

### RISK-01 - Medium - Full regression suite is not green because rounding test drifted

- **Observed:** `tests/interest-rounding.test.js` fails while the other 45 test files pass.
- **Root cause:** [interest-rounding.test.js](../tests/interest-rounding.test.js) still asserts older static source fragments such as `_roundInterestDown10(standardLoanAmount*0.20)`. The current implementation in [index.html](../www/index.html) uses `_roundInterestDown10()` as a legacy-named helper which rounds **up to Rs.5**, matching the newer requested rule and the test's own numerical expectations.
- **Affected module/functions:** `tests/interest-rounding.test.js`; `_roundInterestDown10`, `_periodInterestGross`, `_interestProratedThroughDate`, `_topUpInterestSplit` in `www/index.html`.
- **Impact:** automated release gate cannot prove all tests are green; a real rounding regression could be masked by the stale assertion.
- **Required fix order:** update the test contract and add exact cross-surface rounding assertions without changing stored historical transactions.

### RISK-02 - High - Expense and non-account deletion is not append-only in the SQLite projection

- **Observed:** [index.html](../www/index.html) `deleteExpense()` and `deleteNatTxn()` remove rows directly from live arrays. [sqliteDataIntegrity.js](../www/js/sqliteDataIntegrity.js) `entityRows()` only upserts current `expenses`/`nonAccount` rows; unlike loan and payment handling, `persistState()` does not create tombstones for missing expense/non-account rows or verify their normalized table totals before commit.
- **Affected module/functions:** `deleteExpense`, `deleteNatTxn`; `entityRows`, `persistState`, `currentLedgerMetrics`, `dbMigrationMetrics`.
- **Impact:** the SQLite normalized `expenses`/`non_account_transactions` tables can retain stale rows after a delete while current `app_state` hides them. A later direct SQL-based report, restore, or sync may disagree with the visible app state.
- **Required fix order:** introduce reversal/tombstone records for expense/non-account delete/edit, soft-delete their normalized rows, include their counts/totals in pre-commit verification, and add crash/restart/sync tests.

### RISK-03 - High - RBAC is not enforced across financial and backup workflows

- **Observed:** `_mumIsAdmin()` guards user-management and audit-clear actions, but financial and data-sensitive functions such as `saveBorrower`, `deleteBorrower`, `saveEntry`, `saveEditPayModal`, `saveTopUp`, `deleteTopUp`, `exportData`, import/restore, and sync/backup entry points have no role authorization guard. The client gateway accepts one bearer token and proxies it; it does not establish per-user permissions.
- **Affected module/functions:** `www/index.html` `_mumIsAdmin`, `saveBorrower`, `deleteBorrower`, `saveEntry`, `saveEditPayModal`, `saveTopUp`, `deleteTopUp`, `exportData`, `importData`; `mobile-apk-download/worker/gateway-api.ts` `handleGatewayApi`.
- **Impact:** a Collector/Agent session can invoke sensitive global client functions or requests unless the UI happens to hide a button. Local role storage is not an authoritative authorization boundary.
- **Required fix order:** define permission matrix; enforce it before every client action and independently at the gateway/upstream; bind gateway token to a user/device/business/role; deny by default and log denied attempts.

### RISK-04 - Medium - Native/provider workflows are not device-verified by this audit

- **Observed:** JavaScript and source tests cover contracts, but no Android device was connected for native Google Sign-In, Drive, SAF picker/export, WhatsApp/image share, biometric, dialer, notification/permission, update install, or system-back verification.
- **Affected module/functions:** `android/app/src/main/java/in/vasoolbook/app/MainActivity.java`; `www/js/driveService.js`; `www/cloud-storage.js`; `www/sql-server.js`.
- **Impact:** build/static correctness does not guarantee runtime behavior for OEM WebViews, Google Play Services, installed share targets, Android 13-15 storage, or provider network failures.
- **Required fix order:** execute WF-26 device matrix on a signed debug/release-compatible device before release.

### RISK-05 - Low - Native Google setup guide is stale relative to current configuration behavior

- **Observed:** [TESTING.md](../TESTING.md) describes a placeholder fallback, whereas [capacitor.config.js](../capacitor.config.js) currently throws when no valid `GOOGLE_WEB_CLIENT_ID` is available.
- **Affected module/files:** `TESTING.md`; `capacitor.config.js` `requireWebClientId`.
- **Impact:** a developer may follow an obsolete build instruction and misdiagnose an intentional configuration failure.
- **Required fix order:** align the guide with the current strict Web OAuth client ID requirement.

## Prioritized fix order

1. **RISK-02:** make expense/non-account corrections append-only/tombstoned and add normalized-table reconciliation.
2. **RISK-03:** implement server-enforced RBAC plus client guards for every privileged financial/data action.
3. **RISK-01:** repair the stale interest-rounding test contract and restore a fully green release gate.
4. **RISK-04:** run and record the Android device/provider test matrix; fix only observed native failures.
5. **RISK-05:** update developer documentation after runtime behavior is confirmed.

## Mandatory regression matrix for every future financial change

For each affected workflow, run: normal save, duplicate-click, partial payment, advance payment, previous pending due, edit, delete/reversal, refresh, app restart, offline mode, midnight/date boundary, area switch, legacy import, corrupted backup rejection, merge restore, provider timeout, cancelled action, and post-operation count/total/checksum comparison.

## Release gate

Do not build a release APK until all applicable rows are PASS-A or manually verified, no Critical/High finding is open, and the full automated suite reports zero failures.
